# 슬라임 키우기

때려서 젤리를 모으고, 먹여서 레벨을 올리고, 레벨이 오르면 젤리가 더 빨리 모이는 방치형(idle) 게임.
의존성 없는 단일 HTML 파일이라 `index.html`을 브라우저로 열면 바로 실행된다.

## 실행

`index.html`을 더블클릭한다. 끝.

저장이 안 된다는 메시지가 뜨면(브라우저가 `file://`에서 localStorage를 막는 경우) 이 폴더에서 로컬 서버를 띄우고 `localhost:8000`으로 접속한다.

```
python -m http.server
```

## 담고 있는 것

방치형 장르의 필수 요소 다섯 개가 모두 들어 있다.

| 시스템 | 구현 |
|---|---|
| 수동 획득 | 슬라임 때리기, 확률적으로 크리티컬(젤리 2배) |
| 타격감 | 스쿼시 + 파문 + 젤리 방울 + 피격 표정, 크리 시 금색 확대판 + 진동 |
| 자동 획득 | 젤리밭의 초당 수익 |
| 전투 | 공격력으로 몬스터 자동 사냥, 층이 오를수록 체력 상승 |
| 업그레이드 | 손맛 · 행운 · 젤리밭 · 소화력 · 힘 훈련 (비용이 지수로 상승) |
| 무기 | 6종, 20레벨마다 해금. 하나만 장착, 환생해도 유지 |
| 저장 / 오프라인 보상 | localStorage + 경과 시간 계산, 상한 8시간 |
| 환생(프레스티지) | 레벨 20 이상에서 영혼 획득, 영구 배율 |

핵심 순환은 이렇게 닫힌다.

```
젤리 -> 먹이 -> 레벨 -> 공격력 상승 -> 사냥 가속 -> 젤리
```

## 코드 구조

파일 하나에 다 있고, 주석으로 열 개 구역이 나뉘어 있다. 핵심은 아래 네 층의 단방향 분리다.

- **상태(`state`)** — 저장되어야 하는 값만. 이게 세이브의 전부다.
- **파생 수치(`perClick`, `perSec` …)** — 상태에서 매번 계산하고 **절대 저장하지 않는다.** 저장하면 공식을 바꿀 때 옛 세이브가 틀린 값을 들고 있게 된다.
- **행동(`hit`, `feed`, `buy`, `rebirth`)** — 상태만 바꾸고 화면은 건드리지 않는다.
- **렌더(`render`)** — 상태를 화면에 비추기만 하고 상태를 바꾸지 않는다.

고칠 곳 찾기. 줄 번호는 수정할 때마다 밀리므로 구역 주석으로 찾는다(`Ctrl+F`로 `1.` `2.` 같은 구역 번호 검색).

| 무엇을 바꾸려면 | 어디 |
|---|---|
| 색·글꼴·배치 | `<style>` 블록 |
| 업그레이드 가격·이름·설명 | 구역 1 `UPGRADES` 표 |
| 무기 이름·아이콘·해금 레벨·가격·성능 | 구역 1 `WEAPONS` 표 |
| 무기상점 창 | `<div id="wshop">` 마크업, `<style>`의 `.modal` `.sheet` `.w`, 구역 6 `renderShop` |
| 몬스터 체력·보상 곡선, 몬스터 이름 | 구역 1 `hpOfStage` · `rewardOfStage` · `MONSTERS` |
| 환생 조건, 오프라인 상한, 세이브 키 | 구역 1 하단 상수 |
| 업그레이드의 **실제 효과**, 성장 곡선 | 구역 3 파생 수치 |
| 전투 처리 | 구역 4 `fight` |
| 화면 표시 내용 | 구역 6 `render` |
| 클릭 이펙트(파문·방울·진동) | 구역 9 `burst`, `<style>`의 `.ring` `.bit` `.flash` |
| 슬라임 표정 | 구역 9 `hurtFace`, `<style>`의 `.eye` `.mouth` `.hurtglow` |

## 수치 설계

- **업그레이드 비용** = `기본가 × 성장률^보유수`. 성장률 1.15는 쿠키클리커 이후의 사실상 표준값. 크게 잡으면 금방 벽에 막히고, 작게 잡으면 긴장감이 없어진다.
- **레벨업 요구 경험치** = `50 × 레벨^1.6`. 지수가 1보다 크므로 후반이 느려진다.
- **레벨 보상** = 레벨당 획득량 +5%, 곱셈으로 적용되어 클릭·자동 수익·공격력에 동시에 걸린다.
- **몬스터 체력** = `10 × 층^1.55`, **보상** = `8 × 층^1.25`. 체력의 지수가 보상의 지수보다 크므로 층이 오를수록 사냥이 느려지고, 그래서 힘 훈련에 투자할 이유가 생긴다. **이 두 지수의 차이가 전투 난이도 전체를 결정한다.**
- 기본 체력 10과 기본 공격력 2를 맞춰 **첫 몬스터를 5초에** 잡게 했다. 시작 직후 첫 보상이 몇 초 안에 들어오지 않으면 플레이어가 떠난다.
- **크리티컬** = 기본 5%에서 단계당 +4%, 상한 75%(18단계). 손맛과 달리 기대값이 아니라 *분산*을 파는 업그레이드다. 0단계에서도 5%를 남겨 둔 것은, 한 번도 안 터지면 플레이어가 이 시스템의 존재를 모르기 때문이다. 상한을 100% 미만으로 막지 않으면 확률의 재미가 사라지고 손맛 업그레이드와 완전히 겹친다.

## 무기

우측 상단 ⚔️ 아이콘으로 창이 열린다. 업그레이드와 다른 점은 **한 번만 사고, 하나만 장착한다**는 것.

| 무기 | 해금 | 가격 | 공격력 | 크리 |
|---|---|---|---|---|
| 🪵 나무 막대 | Lv.20 | 1K | +15 | +2% |
| 🪓 돌 도끼 | Lv.40 | 12K | +70 | +4% |
| 🗡️ 녹슨 단검 | Lv.60 | 150K | +320 | +6% |
| ⚔️ 강철 검 | Lv.80 | 2M | +1.5K | +8% |
| 🔥 화염 창 | Lv.100 | 30M | +7K | +11% |
| 🌙 영혼 낫 | Lv.120 | 500M | +35K | +15% |

공격력 보너스는 `힘 훈련`과 같은 자리에 더해지므로 레벨·영혼 배율을 그대로 받는다. 크리는 `행운`과 합산된다.

설계에서 중요한 세 가지.

- **가격이 성능보다 빨리 오른다.** 등급당 공격력 약 4.7배, 가격 약 15배. 그래서 다음 무기는 항상 한참 모아야 하는 목표로 남는다.
- **환생해도 사라지지 않는다.** 영혼과 같은 취급이다. 매 판 다시 사야 한다면 5억짜리 낫을 살 이유가 없고 상점 자체가 죽는다. `rebirth`에서 `weapons`/`equipped`를 따로 챙긴다.
- **크리 상한이 두 개다.** `CRIT_UP_CAP`(0.75)은 `행운`만으로 도달 가능한 선, `CRIT_CAP`(0.90)은 무기까지 더한 전체 상한. 최고 무기의 +15%가 정확히 그 차이를 메우도록 맞췄다. 이게 어긋나면 마지막 무기가 "이미 상한이라 의미 없는" 물건이 된다.

무기를 추가하려면 `WEAPONS` 표에 행만 넣으면 된다. 효과 계산식(`weaponAtk`/`weaponCrit`)은 표를 그대로 읽으므로 손댈 필요가 없다 — 업그레이드와 다른 점이다.

## 업그레이드 추가하기

두 곳을 고쳐야 한다. 표는 가격과 표시만 담당하고, 효과는 파생 수치에 있다.

1. `UPGRADES` 표에 행 추가 (`state.up`의 키는 자동 생성된다)

```js
{ id: 'friend', name: '친구 슬라임', base: 2000, growth: 1.30,
  desc: n => `초당 젤리 +${n * 5}` },
```

2. 효과를 계산식에 반영

```js
const perSec = () => (0.5 * state.up.field + 5 * state.up.friend) * levelMult() * soulMult();
```

상한을 두고 싶으면 표의 행에 `maxed`를 함께 넣는다. `render`가 이걸 보고 비용 자리에 `MAX`를 찍고 버튼을 잠근다(`행운`이 이 방식이다).

```js
{ id: 'friend', name: '친구 슬라임', base: 2000, growth: 1.30,
  desc:  n => `초당 젤리 +${n * 5}`,
  maxed: n => n >= 20 },
```

## 이펙트 다루기

`burst`가 클릭 한 번마다 DOM 노드를 만든다. 평타 6개, 크리 12개.

**노드는 반드시 스스로 지워져야 한다.** `animationend`에서 `remove()`를 부르는 게 그 장치다. 이걸 빼면 연타 1분에 수천 개가 쌓여 눈에 띄게 느려진다. 이펙트를 새로 추가할 때도 같은 규칙을 지킨다.

애니메이션은 `transform`과 `opacity`만 건드린다. `left`/`width` 같은 속성을 움직이면 매 프레임 레이아웃을 다시 계산해서 저사양 폰에서 끊긴다.

방울 개수·거리는 `burst` 안의 `n`과 `dist`로 조절한다. 저사양 기기를 노린다면 개수를 먼저 줄인다.

OS에 '동작 줄이기'가 켜져 있으면 `prefers-reduced-motion` 규칙이 모든 애니메이션을 0.01ms로 만든다. 이펙트는 사실상 안 보이지만 노드 정리는 그대로 동작한다.

## 슬라임 표정

눈과 입은 `.slime` 안의 실제 요소다(`.eye.l` `.eye.r` `.mouth`). 의사요소로 두지 않은 이유는, 아플 때 눈 하나를 `>` 모양의 두 획으로 쪼개야 해서 눈마다 `::before`/`::after`가 따로 필요하기 때문이다. 두 획의 `transform-origin`을 꼭짓점에 두면 회전만으로 `><`가 만들어진다.

붉게 달아오르는 기운은 `filter`가 아니라 `.hurtglow` 레이어다. **`render()`가 매 프레임 `.slime`의 인라인 `filter`(레벨별 색조)를 덮어쓰기 때문에 클래스로 건 `filter`는 무조건 진다.**

표정 지속은 `hurtFace`의 260ms. 스쿼시(90ms)보다 길어야 표정이 읽힌다. 연타하면 `clearTimeout`으로 타이머가 계속 밀려서 때리는 내내 찡그린 얼굴이 유지된다.

## 세이브 다루기

**"고쳤는데 게임이 안 바뀐다"의 원인은 거의 항상 이전 세이브다.**

- 연습 중 초기화 — `F12` → Console에 `localStorage.clear(); location.reload();`
- 밸런스를 크게 뒤엎었을 때 — `SAVE_KEY`의 `v1`을 `v2`로 올린다. 기존 세이브가 무시된다.
- 후반 테스트 — Console에 `state.jelly = 1e9; state.level = 30;`

세이브는 브라우저별·도메인별이다. PC에서 키운 것을 폰에서 이어서 할 수는 없다. 그러려면 서버와 로그인이 필요하다.

## 배포

외부 리소스 참조가 0개인 자기완결 파일이라 어디에 올려도 그대로 동작한다.

- **GitHub Pages** — 무료, 영구 URL, `index.html`을 그대로 서비스하므로 사본이 생기지 않는다.
- **itch.io** — 실제 게임 유통 플랫폼. 방치형을 찾아서 노는 사용자가 모여 있다.
- **Netlify Drop / Cloudflare Pages** — 폴더를 드래그&드롭하면 즉시 URL이 나온다.

배포하면 소스가 100% 공개되고 콘솔로 치트가 가능하다. 싱글플레이라 문제되지 않지만, 랭킹을 넣는다면 서버 검증이 필요해진다.
